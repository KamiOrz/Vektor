# Vektor v7.0 Product Requirement Document

## 1. 产品概述

### 1.1 产品定义

Vektor v7.0 是一个面向移动端的极简 M3U 播放客户端。用户通过扫描二维码或载入剪贴板中的 M3U/HLS 链接进入播放，无账号、无首页、无内容推荐、无复杂设置。

产品只有两个核心状态：

- **状态 A：扫码态**：获取有效 M3U 链接。
- **状态 B：播放态**：解析 M3U 并播放频道。

### 1.2 目标平台

- iOS：使用 `AVPlayer` 作为视频播放内核。
- Android：使用 `Media3 ExoPlayer` 作为视频播放内核。
- 双端均必须支持 HLS `.m3u8` 视频流、后台音频播放和系统锁屏控制。

### 1.3 目标用户

- 已拥有 M3U 播放源的用户。
- 需要快速扫码播放、低干扰观看、频繁切台的用户。
- 偏好暗色、高对比、手势驱动体验的重度观看用户。

### 1.4 核心原则

- **零前置路径**：无启动页、无登录、无欢迎引导，打开即进入可用状态。
- **双状态闭环**：扫码态只负责取链接，播放态只负责解析、播放、切台。
- **资源优先级明确**：扫码成功后必须释放摄像头，把硬件资源交给视频解码。
- **秒开优先**：优先解析前 5 个频道并启动第一个频道播放，完整列表后台加载。
- **无按钮优先**：播放中的高频操作以手势为主，按钮只保留必要的隐式触发区。

## 2. 状态机与启动规则

### 2.1 状态定义

| 状态 | 进入条件 | 退出条件 | 主要资源 |
| --- | --- | --- | --- |
| 扫码态 | 无历史链接、历史链接失效、用户重回扫码 | 获取到有效 M3U 链接 | 摄像头、剪贴板读取 |
| 播放态 | 获取到有效 M3U 链接，或启动时恢复有效历史链接 | 用户重回扫码、链接失效且无法恢复 | 播放器、网络、图片缓存 |

### 2.2 启动恢复

App 启动时按以下顺序执行：

1. 读取本地保存的最后一次有效 M3U 链接。
2. 若没有历史链接，直接进入扫码态。
3. 若存在历史链接，发起轻量可用性检查。
4. 若链接可访问并返回可解析 M3U 内容，直接进入播放态。
5. 若链接不可访问、超时、返回非 M3U 内容或解析为空，清除该链接并进入扫码态。

启动恢复不得显示独立启动页。检查过程中可使用当前目标状态的骨架画面或轻量加载反馈。

### 2.3 持久化规则

- 仅保存最后一次验证成功的 M3U 链接和必要的播放恢复信息。
- 不保存账号、用户身份、云端同步数据。
- 可保存最近一次频道索引，但默认恢复策略仍以“确保能播放”为优先；若该频道失效，应自动回退到列表中第一个可播放频道。

## 3. 状态 A：扫码态

### 3.1 进入行为

- 进入扫码态后自动请求摄像头权限。
- 摄像头权限已授权时，自动打开后置摄像头并开始识别二维码。
- 摄像头权限未授权时，显示权限说明与系统授权入口，同时继续检测剪贴板。
- 扫码态界面保持全屏取景，不提供登录、搜索、频道列表或设置入口。

### 3.2 二维码识别

识别逻辑必须实时解析二维码文本，并只接受符合以下条件的内容：

- 字符串是标准 URL。
- URL 以 `http://` 或 `https://` 开头。
- URL 本身或响应内容可判定为 M3U/HLS 相关资源。

以下情况判定为识别失败，但不得中断扫描：

- 非 URL 文本。
- 非 HTTP/HTTPS 协议。
- URL 格式非法。
- URL 可访问但不是 M3U 内容。
- M3U 内容为空或没有可播放频道。

### 3.3 M3U 判定

实现时至少支持以下判定方式：

- URL 路径或查询参数包含常见 M3U 标记，例如 `.m3u`、`.m3u8`、`playlist`。
- HTTP 响应内容以 `#EXTM3U` 开头或包含有效 `#EXTINF` 条目。
- 响应状态为成功，且最终解析得到至少 1 个可用 `Stream URL`。

如果 URL 本身无法静态判定，应允许发起网络探测；探测失败时留在扫码态并展示轻量错误反馈。

### 3.4 剪贴板辅助

- 扫码态实时检测系统剪贴板。
- 当剪贴板存在合法 M3U/HLS 链接时，在底部提示区展示“载入剪贴板链接”的触发区。
- 用户触发后，按与二维码一致的校验流程处理该链接。
- 剪贴板内容非法时，不弹窗打扰，只保持底部默认提示。

### 3.5 成功反馈与资源释放

识别到有效 M3U 链接后：

1. 立即触发一次短促物理震动。
2. 保存该链接为最后一次有效 M3U 链接。
3. 下一帧销毁扫码会话并释放摄像头资源。
4. 停止后台图像采集、二维码识别和摄像头预览。
5. 切换到播放态并开始 M3U 拉取解析。

摄像头释放是硬性验收项。进入播放态后不得继续占用摄像头。

### 3.6 扫码态异常

| 异常 | 表现 | 恢复方式 |
| --- | --- | --- |
| 摄像头无权限 | 保留扫码视觉框架，提示授权 | 用户跳转系统设置授权，或使用剪贴板 |
| 摄像头不可用 | 显示设备不可用提示 | 用户重试或使用剪贴板 |
| 无网络 | 显示网络不可用提示 | 网络恢复后自动或手动重试 |
| 链接非法 | 轻量提示，不打断扫描 | 继续扫描或替换剪贴板 |
| M3U 为空 | 轻量提示，不保存链接 | 继续扫描 |

## 4. 状态 B：播放态

### 4.1 进入行为

- 播放态接收一个已通过校验的 M3U URL。
- 进入后立即发起 M3U 文本拉取。
- 解析出前 5 个频道后即可渲染频道信息并默认播放第一个频道。
- 剩余频道继续在后台解析，不阻塞播放、抽屉操作或切台。

### 4.2 本地频道模型

每个频道至少包含以下字段：

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `id` | 本地生成 | 稳定列表索引或哈希，用于 UI diff 和当前频道定位 |
| `streamUrl` | M3U 流地址 | 必填，视频播放源 |
| `title` | `#EXTINF` 标题 | 必填；缺失时使用“Channel {index}” |
| `logoUrl` | `tvg-logo` | 可选，频道封面或台标 |
| `group` | `group-title` | 可选；缺失时归入 `Ungrouped` |
| `index` | 本地生成 | 从 1 开始的频道序号 |

解析器应容忍常见 M3U 变体，忽略无法形成有效 `streamUrl` 的条目。

### 4.3 流式解析与秒开

- 首批目标：前 5 个有效频道。
- 首批解析完成后立即允许播放和列表展示。
- 完整列表解析完成前，抽屉中可展示“正在加载更多频道”的底部状态。
- 后台解析失败不得影响已解析频道播放。
- 如果前 5 个频道全部不可播放，应继续尝试后续频道，直到找到第一个可播放频道或确认列表无可用频道。

### 4.4 视频播放

- iOS 使用 `AVPlayer`，Android 使用 `Media3 ExoPlayer`。
- 必须启用系统硬件解码能力。
- 必须支持 HLS `.m3u8`。
- 解析成功后默认播放第一个可播放频道。
- 点击频道列表任意频道后，播放器立即切换数据源并重新加载。
- 切台时抽屉自动收起，让屏幕回到观看优先状态。

### 4.5 后台与锁屏控制

播放态必须支持：

- App 退到后台后音频继续播放。
- 锁屏后音频继续播放。
- 系统锁屏控制中心展示当前频道名称。
- 系统锁屏控制中心支持暂停和恢复。

不要求在 v7.0 中实现复杂节目单、封面富媒体或进度拖拽；直播流无法提供时长时，应隐藏时长展示或显示直播状态。

### 4.6 Logo 图片缓存与降级

- `logoUrl` 采用异步下载，不阻塞频道列表渲染。
- 下载成功后缓存到本地图片缓存。
- 图片加载失败、链接为空或格式不支持时，展示频道序号或频道缩写。
- 图片缓存失败不得影响播放。

### 4.7 频道抽屉

播放态采用上下双层结构：

- 上方为 16:9 视频播放区。
- 下方为当前频道信息和抽屉触发区。
- 用户从下方区域向上滑动，拉出频道列表抽屉。

抽屉要求：

- 默认收起，展示当前频道和上滑提示。
- 展开高度约为屏幕高度的 60%，可根据安全区适配。
- 顶部提供横向滚动分组筛选。
- 分组来源于频道模型的 `group` 字段。
- 选中分组后，下方长列表联动过滤。
- 当前频道以绿色高亮、左侧竖条或播放图标标识。
- 点击频道后立刻切换播放源，并自动收起抽屉。

### 4.8 手势控制

播放态不依赖传统独立按钮完成高频操作。

| 手势 | 生效区域 | 行为 |
| --- | --- | --- |
| 左右滑动 | 抽屉收起时的屏幕下半部分 | 上一个/下一个频道 |
| 上滑 | 下方信息触发区 | 展开频道抽屉 |
| 下滑 | 抽屉区域 | 收起频道抽屉 |
| 上下滑动 | 视频左半区 | 调整系统屏幕亮度 |
| 上下滑动 | 视频右半区 | 调整系统媒体音量 |
| 双指下滑 | 全局 | 销毁播放器并回到扫码态 |

音量手势应尽量拦截系统默认音量弹窗。若平台限制无法完全拦截，应保持应用内反馈一致，并在平台实现文档中记录差异。

### 4.9 重回扫码

用户通过双指下滑或视频右上角极小常驻触发区重回扫码时：

1. 停止当前播放。
2. 销毁播放器实例。
3. 释放音频焦点、后台播放会话和视频解码资源。
4. 保留最后一次有效链接，除非用户明确清除。
5. 切换到扫码态并重新打开摄像头。

该流程不得出现播放器音频残留、后台继续拉流或摄像头无法重新打开的问题。

### 4.10 播放态异常

| 异常 | 表现 | 恢复方式 |
| --- | --- | --- |
| M3U 拉取失败 | 播放区显示轻量错误 | 重试；多次失败后回扫码态 |
| M3U 无有效频道 | 显示无可播放频道 | 清除本次链接并回扫码态 |
| 当前频道播放失败 | 当前项标记失败 | 自动尝试下一个频道或用户手动切台 |
| 图片加载失败 | 展示频道序号/缩写 | 后台可重试，不影响播放 |
| 后台播放被系统中断 | 暂停并记录状态 | 回前台后允许恢复播放 |

## 5. 视觉与交互要求

详细设计规范见 `docs/design.md`。产品验收中以 PRD 的双状态原则为准，设计稿中的示例频道、示例图片、底部导航仅作为视觉参考，不代表新增账号、推荐、搜索或复杂设置模块。

核心视觉要求：

- 主背景使用 OLED 友好的纯黑或近黑。
- 活跃态使用 Neon Green。
- 扫码态必须有全屏取景、扫描框、绿色扫描线和底部提示。
- 播放态必须突出 16:9 视频区、当前频道信息和隐藏式频道抽屉。
- UI 控件保持低干扰，播放时控制层自动淡出。

## 6. 非功能要求

### 6.1 性能

- App 冷启动后应直接进入目标状态，不出现独立启动页。
- 扫码识别成功到播放态切换应尽量在 1 秒内完成资源释放和解析启动。
- 首批频道解析完成后应立即允许播放，不等待完整列表。
- 频道切换应快速响应，并提供明确加载反馈。

### 6.2 资源与电量

- 扫码态退出后必须释放摄像头。
- 播放态退出后必须释放播放器和音频会话。
- 图片下载和后台解析不得抢占视频解码关键资源。
- 暗色视觉系统应优先适配 OLED 低功耗场景。

### 6.3 权限

- 摄像头权限仅用于扫码。
- 剪贴板读取仅用于检测 M3U/HLS 链接。
- 后台音频权限仅用于播放态持续播放。
- 不采集用户身份信息。

### 6.4 缓存

- 保存最后一次有效 M3U 链接。
- 可缓存频道 Logo。
- 可缓存最近一次频道索引。
- 不要求缓存完整 M3U 内容；如实现缓存，必须保证启动时仍做可用性检查。

### 6.5 日志与可观测性

本地开发和测试版本应能记录以下事件：

- App 启动目标状态。
- 扫码成功/失败原因。
- 剪贴板链接检测和载入结果。
- M3U 拉取耗时、解析频道数、首批频道耗时。
- 播放器初始化、切台、播放失败。
- 摄像头释放和播放器销毁结果。

日志不得记录完整私密播放源；如需排查，可记录脱敏 URL。

## 7. 验收标准

### 7.1 扫码态验收

- 首次启动无历史链接时直接进入扫码态。
- 摄像头授权后自动打开并识别二维码。
- 非 HTTP/HTTPS、非 URL、非 M3U 内容不会切换到播放态。
- 剪贴板存在合法 M3U 链接时出现载入入口。
- 识别成功后有短震动反馈。
- 进入播放态后摄像头资源已释放。

### 7.2 播放态验收

- 有效 M3U 链接能进入播放态并默认播放第一个可播放频道。
- 前 5 个频道优先解析并展示，剩余频道后台加载。
- 频道标题、Logo、分组能正确从 M3U 标签提取。
- Logo 缺失或失败时显示频道序号/缩写。
- 抽屉能上滑展开，按分组筛选频道。
- 点击频道后立即切台并自动收起抽屉。
- 左右滑动能切换上/下一个频道。
- 双指下滑能销毁播放器并回到扫码态。

### 7.3 平台能力验收

- iOS 使用 `AVPlayer` 播放 HLS。
- Android 使用 `Media3 ExoPlayer` 播放 HLS。
- 退到后台或锁屏时音频持续播放。
- 锁屏控制中心支持暂停/恢复。
- 亮度和音量手势在对应平台可用；平台限制需记录。

### 7.4 回归验收

- 无账号、无登录、无欢迎引导。
- 无首页、推荐流、云同步、搜索或复杂设置页。
- 历史链接有效时重启自动进入播放态。
- 历史链接失效时重启进入扫码态。
- 多次扫码态和播放态切换后，摄像头和播放器资源不残留。
